## Evidence interpretation and cutover blockers

### Additional evidence recorded on 2026-10-12

- The packaged-image live script now checks 15 denied candidate direct links across region and store managers and a store beacon assign → release → reassign lifecycle. It also checks foreign beacon, store, region, layout-context, catalog, recipe, category-write, and log API denials. These are real Keycloak/Quarkus responses; they do not cover every UI action in the route rows above.
- `categories.spec.ts` and `diagnostics.spec.ts` now cover keyboard operation and explicit empty/error/retry states with request suppression for unauthorized users. Their row-level gaps are therefore narrower than the original table text. The remaining gaps are authenticated live route/action persistence and full legacy parity.
- `editor.spec.ts` now covers keyboard canvas placement/movement, JSON import/export and undo, persisted shelf layout code/product positions/access angle, invalid-code publication blocking, duplicate beacon option prevention, and critical deletion confirmation. These use mocked APIs. The live image tests publication and scope; a full keyboard and accessibility pass remains open.
- The current image's live store-editor workflow now changes those shelf fields through the inspector, saves a draft, publishes it, and checks the anonymous active-layout JSON. The browser suite also checks legacy cashier deletion confirmation, named publication warnings, and correctly sized SVG editor handles. The selected-shelf live capture is in `screenshots/store-editor-inspector.png`.
- The live store editor also moves a shelf by keyboard, undoes and redoes the move, then publishes the resulting geometry. The anonymous active-layout response confirms the final `x` coordinate.
- The live store editor exports its current JSON, imports it with an additional navigation metadata marker, saves/publishes it, and confirms that marker survives both public publication and later version recovery.
- After concurrent store-layout activations, the live script reactivates the prior published version and confirms the anonymous response returns its geometry and metadata with exactly one active version. This is data recovery evidence, separate from route-flag rollback.
- The grown OpenSearch layout index exposed an unsorted global history query that could omit the just-published version. The backend now filters version documents and sorts by `savedAt` before limiting; the packaged live run confirms immediate visibility.
- Admin diagnostics now loads real audit and error logs in the candidate UI and refreshes by keyboard. Region/store-manager direct-link and API denials were already part of the live role check.
- Both manager dashboards now compare rendered region, store, free-beacon, and missing-layout counts to their scoped live API responses and suppress admin-only activity.
- The candidate recipe UI now creates a draft with a catalog product ingredient and step, persists both, keeps the draft private, and publishes it for anonymous mobile retrieval. The separate edit/publish/deactivate path remains covered.
- The candidate beacon UI reviewed and committed a two-row bulk creation with a shared UUID and separate minors; authenticated API reads confirmed both identities.
- Beacon assignment can now load stores beyond the first 100; a browser regression assigns to store 101. Assigned beacon responses include the store's region ID, which the live scoped response confirms.
- An admin then archived the store created through the region-manager candidate form; the API returned `ARCHIVED` and the anonymous mobile store list omitted it.
- Before archival, the region manager assigned and released a free beacon from the candidate Store detail page. The store-beacon API confirmed both post-states.
- After archive, the same detail page showed the server's “Filiale archiviert” audit entry; the store audit endpoint included the `ARCHIVE` action.
- The current candidate browser suite additionally covers pointer move/resize/rotate/undo and route keyboard/empty/load-error/retry states for regions, stores, store detail/create, beacons, products, recipes, categories, and diagnostics. The local live stack confirms candidate product edit and category create/edit persistence via anonymous catalog reads. These narrow the listed rows' gaps; per-route live fault states and complete legacy action parity still gate switching.
