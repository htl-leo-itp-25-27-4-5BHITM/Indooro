Warum die Tests so viel Laufzeit brauchten

~1.600

Minuten Laufzeit im November (Nutzungsseite von GitHub)

31 min

dauert ein iOS-Testlauf auf dem Mac

0 $

Kosten: Unser Repo ist öffentlich, dort sind GitHub-Runner gratis

  • Bis zu 9 KI-Agenten arbeiten gleichzeitig, jeder pusht auf seinen eigenen Pull Request
  • Jeder Push startete alle Tests, auch wenn sich nur Doku oder eine Webseite änderte
  • Alte Läufe liefen weiter, obwohl schon ein neuerer Push da war
  • Entwürfe und wackelige Tests (Zeitüberschreitung, Maven 429) kosteten Extra-Läufe
Wichtig, damit niemand falsch rechnet: Unser Repo ist öffentlich. Für öffentliche Repos sind die normalen GitHub-Runner gratis, auch der Mac, und zählen nicht ins Monatskontingent. Die GitHub-API meldet für unsere Läufe 0 abrechenbare Minuten. Die Nutzungsseite zeigt trotzdem die Laufzeit an, im November ungefähr 1.600 Minuten. Das Problem war also nicht Geld, sondern Zeit: Mit vielen KI-Agenten gleichzeitig startete jeder Push die ganze Pipeline, Läufe standen in der Warteschlange, und die Rückmeldung auf einen Pull Request kam spät. Der Mac-Lauf mit 31 Minuten war der langsamste Teil. Würde das Repo privat, würde es teuer: Dann zählt eine Mac-Minute zehnfach.
