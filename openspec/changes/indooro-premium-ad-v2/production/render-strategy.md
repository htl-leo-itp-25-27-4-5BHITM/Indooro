# Preview-first render strategy — future work only

The original concept revision produced no media. After separate user approvals, the four draft prototypes, navigation shots and a **780-frame / 26-second 1280×720** rough cut were generated. P1 opening/clarity covers 0–119, P2 smartphone/search 120–179, P3 phone-to-store 180–299, P5–P7 navigation 300–539, and P4 destination/brand 540–779. The new preview has original scratch sound and no VO. Final-quality rendering remains gated by rough-cut review and explicit picture lock.

For 3D, start with planned stills and a 1–2 s low-sample movement before each full prototype. Keep frame-numbered passes, depth/ID/matte where needed, camera projection data and a hash manifest. If 3D fails visual or time limits, use the specified continuous 2.5D Remotion fallback while retaining each signature idea. Inspect route continuity around screen crossing, 720p UI and shopper legibility, destination endpoint and final 75-frame static hold. Watch the prototypes at normal speed muted and with temporary audio; then record an accept/revise decision.

Navigation shots 05–07 and the full 720p rough cut are rendered. Picture-lock and final-mix gates precede a separately approved 1920×1080 H.264/AAC master. Verify 780 frames at 30 fps if 26 seconds remains final, codec/pixel format, shot boundaries, no blank frames, color/route continuity, claims/rights, loudness/peak and actual human watch/listen results. Any justified runtime change must update storyboard, audio cues, tasks and technical contracts together. Generated media can remain outside Git if scripts, provenance, hashes and delivery location are recorded.
