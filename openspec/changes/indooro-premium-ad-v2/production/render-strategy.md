# Preview-first render strategy — future work only

No V2 scene, Blender project, preview or soundtrack is created during this concept revision. After explicit prototype approval, use 30 fps and the proposed **780-frame / 26-second** timeline. Render **only four short 1280×720 draft sequences**: P1 opening/clarity (0–119), P2 smartphone/search (120–179), P3 continuous phone-to-store (180–299), P4 destination/brand (540–779). P4 may be sampled in shorter ranges first to control render cost. Temporary cleared audio and authorized scratch VO are optional for review. The 10–18 s navigation sequence is blocked until prototype acceptance.

For 3D, start with planned stills and a 1–2 s low-sample movement before each full prototype. Keep frame-numbered passes, depth/ID/matte where needed, camera projection data and a hash manifest. If 3D fails visual or time limits, use the specified continuous 2.5D Remotion fallback while retaining each signature idea. Inspect route continuity around screen crossing, 720p UI and shopper legibility, destination endpoint and final 75-frame static hold. Watch the prototypes at normal speed muted and with temporary audio; then record an accept/revise decision.

After explicit prototype acceptance, build navigation shots 05–07 and a full 720p rough cut. Picture-lock and final-mix gates precede a separately approved 1920×1080 H.264/AAC master. Verify 780 frames at 30 fps if 26 seconds remains final, codec/pixel format, shot boundaries, no blank frames, color/route continuity, claims/rights, loudness/peak and actual human watch/listen results. Any justified runtime change must update storyboard, audio cues, tasks and technical contracts together. Generated media can remain outside Git if scripts, provenance, hashes and delivery location are recorded.
