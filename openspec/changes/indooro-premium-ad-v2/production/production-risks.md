# Production risks and decision triggers

| Risk | Evidence/trigger after approval | Response |
|---|---|---|
| Shopper looks like a toy or disappears in wide shots | First 720p figure/store prototype fails human-story read | Adult silhouette, restrained poses/rim light, closer framing; use 2.5D fallback before full asset build |
| Blender unavailable or automation fragile | Executable/version preflight or short background render fails | Keep Remotion-only SVG/CSS/parallax version with identical storyboard and audio cues; C4D is not an assumed rescue path |
| 3D passes and UI mismatch | Phone screen or path handoff changes scale/tangent/color | Shared layout, fixed camera presets, matched tangent and a small proof render |
| Render cost expands | Short pass exceeds practical time budget | Limit 3D to hero shots, reduce geometry/samples, cache sequences or switch to 2.5D |
| Abstract store becomes V1-style diagram | First-viewer preview cannot follow shopper's decision | Reframe around figure/phone/product, remove technical labels, shorten overhead views |
| Route suggests shipping AR or measured accuracy | Claim review finds ambiguous store-space path | Treat path as editorial visualization; keep actual illustrative UI distinct and omit metrics |
| 28 seconds is too fast | `Milch`, destination or found moment missed at 720p | Extend clarity beats inside 25–30 s; do not add feature chapters |
| Voice/music sound synthetic or mask meaning | Human listener rejects dry VO or phone-speaker mix | Alternate authorized German take, simplify cue, duck music; signal checks alone cannot approve audio |
| Brand/rights uncertain | Logo, TTS or music source lacks approved use | Hold final output until source/license documented; replace with owned asset |

All risks remain planning observations; prototype and listening evidence can only be gathered after user approval.
