# Proposed V2 technical architecture — no implementation yet

After explicit approval create `indooro-ad-v2/` as a separate pinned Remotion/React/TypeScript package. Planned tree: `src/timeline/` for exact frame/cue constants, `src/shots/` for 16 shot compositions, `src/ui/` for truthful screen states, `src/map/` for the illustrative walkable route, `src/graphics/` for tracked overlays and identity, `src/audio/` for stem timing, `public/footage/`, `public/audio/{voice,music,sfx,location}/`, `public/brand/`, `previews/`, `exports/`, `scripts/`, plus a rights manifest. Do not import V1 package paths at runtime; copy selected helpers with provenance and tests only after approval.

Remotion will assemble approved filmed plates, UI composites, typography, map/route animation and stems at 30 fps. Shot timing is half-open and centralized; 960 frames is the initial composition, adjustable after a performed VO and rough cut. Use deterministic frame interpolation and a documented camera coordinate transform to bind route overlays to footage. Track a small number of fixed aisle points; where tracking cannot hold, replace the overlay with a clear phone-to-map graphic cut rather than fake spatial precision. Preserve footage original resolution and color profile; generate graded intermediates only after rights and editorial selection.

No backend process is required for rendering. The canonical Swift views and current OpenSpec specs are reference for search/map copy and interaction; product mockups remain labeled if illustrative. Real screen capture is preferable when a stable demonstrable state exists. A phone screen composite must align exposure, reflections, finger occlusion and perspective. A physical route overlay is editorial visualization, not a feature claim about AR guidance.

Asset manifest fields: id, original path/source URL, author, owner, license/release, intended use, expiry/restrictions, checksum, frame rate/resolution, approval status. The render must fail/prevent final release if required rights or media are missing. Store temporary music and voice as separate stems; do not bake them into footage. Quality checks cover exact frame count, H.264/yuv420p, AAC stereo/48 kHz, loudness/true peak, boundary images, half-resolution text, route geometry and human watch/listen reviews.
