# Swift → Android Paritätsmatrix

Referenzcommit: `501e2f76e404f749ee5e0c6353f765c83aff189f`. Alle Swiftpfade beziehen sich auf die aktive Final-App. Klickbare Belege enthalten die beim Schreiben ermittelte **Zeile und das Symbol**, sodass spätere Zeilenverschiebungen nachvollziehbar bleiben. Backendcodes E01–E17 werden in [API_CONTRACT](API_CONTRACT.md) mit Methode, Payload und Java-Beleg aufgelöst; „lokal“ bedeutet kein Backend.

**Legende:** C = **im Code verifiziert** (statische Stelle, kein Laufzeittest); D = **aus Dokumentation**; A = **Annahme**/geplante Androidentscheidung; N = **nicht feststellbar** ohne Gerät/Runtime. Android-Soll ist überall A bis Implementierung/Abnahme. „C“ bescheinigt ausschließlich die konkrete Beobachtung, keine Fehlerfreiheit. Risiken referenzieren Root-/Entscheidungsgates aus [DEPENDENCIES](DEPENDENCIES.md).

**Testnachweis:** T-Pxx ist für jede Zeile der verpflichtende, noch **offene** Nachweis in [ACCEPTANCE](ACCEPTANCE.md). Die Methoden U/I/UI/G bedeuten Unit/Integration/UI/Gerät. Keine dieser Androidprüfungen wurde in diesem Planungsauftrag ausgeführt. Statischer Ist-Beleg ist bereits die Swiftstelle; ein fehlender Runtimebeleg wird nicht als bestanden ausgegeben.
